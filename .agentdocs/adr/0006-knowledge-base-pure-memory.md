# 知识库纯记忆化与 skill 原子化

`.agentdocs/` 曾同时承担知识库与流程引擎职责(索引文件、任务文档生命周期、done/ 归档),导航与归档的维护仪式多于知识产出。现决定:知识库只放记忆(术语、决策、领域知识),不设索引文件——目录约定、文件名、领域文档首行"何时读"承担导航;`workflow/` 语义改为暂存区,任务结束时先沉淀知识再整目录删除,历史归档依赖 git;编排命令从八个收缩为三个(`/agentdocs-setup`、`/interview`、`/team-dev`),规格定稿并入 interview 终点,贯通切片拆解并入 team-dev,环境审查拆为独立的 env-review,`.agentdocs/` 读写规则唯一归 agent-docs skill,其他 skill 不自带写规则。

## 备选方案

- 保留极小索引(MEMORY.md,每条记忆一行):被否决。它是 index.md 的转世,仍需与文件系统双向同步,且术语、决策、领域知识各有归宿后无内容可登记;
- done/ 归档改为继续保留:被否决。归档文档几乎不再被读,git 历史已是永久归档,done/ 只会无限膨胀。

## 后果

- 新建领域文档依赖命名纪律:文件名自述内容,首行写读取场景;文件多了以后项目自行分组目录,约定不变;
- 历史任务文档与工单不再长期保留,查历史靠 git log,值得留下的"为什么"以 ADR 形式沉淀;
- 判定一个文件该不该存在于知识库,只剩一个标准:它是不是下次开工前值得先知道的记忆。
