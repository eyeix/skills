# 面向 Agent 的写作

写给 agent 消费的任何文档的通用参考:skill、`AGENTS.md`、`CLAUDE.md`、任何被指针引用的文档。载体的写法相同:同一套手段让每次运行产生一致的过程与产物。

写的是 skill 时,读 [SKILL-MECHANICS.md](SKILL-MECHANICS.md) 了解 frontmatter、调用方式选择与路由 skill。

## 上下文指针

**上下文指针**(context pointer)是常驻上下文里指向另一份材料的引用。skill 的 description 是一条;AGENTS.md 里指向某文档的一行也是。指针的措辞决定 agent 何时读取目标材料,因此必达的材料要用强措辞;措辞改不动时才内联正文。

一条指针做两件事:说明材料是什么,列出应触发读取的**分支**(branch,文档处理的不同情形)。常驻指针占用每回合的上下文,因此:

- **领词前置**:触发词放在指针最前面;
- **一个分支一条触发**:同一分支的同义改写合并,只保留不同分支;
- **身份信息让正文承担**:正文已有的内容不在指针里重复。

## 两种负载

新增的每份文档与指针都要花两种预算之一:

- **上下文负载**(context load):常驻材料对 agent 窗口的占用。AGENTS.md 的一行、skill 的 description,无论是否触发都在占用;
- **认知负载**(cognitive load):人需要记住哪些文档存在、何时用哪个。

只靠指针到达的材料,以指针自身一行替代常驻材料;没有任何指针的材料,全部落在认知负载上。

## 信息层级

文档由两类内容构成:**步骤**(steps,agent 依次执行的动作)与**参考**(reference,按需查阅的定义、规则、事实)。每条内容放在三层之一:

1. **文内步骤**:agent 依次要做的事;
2. **文内参考**:按需查阅,平铺的规则集是正当形态;
3. **外置参考**:独立文件,由指针触发时加载。

**渐进披露**(progressive disclosure)是沿阶梯下移以保持顶层可读。分支是披露判据:每个分支都需要的内联,只有部分分支需要的放到指针后面。有步骤的文档里,文内参考过多会淹没步骤。**就近集中**(co-location):概念的定义、规则、注意事项放同一个标题下。**蔓延**(sprawl)是失败形态:文档太长,注意力摊薄,多一行就多一行要维护。因此参考外置,按分支或时序拆分。

## 步骤与完成判据

每个步骤终止于一个**完成判据**:告诉 agent 这步做完了的条件。两个属性决定它的强度:

- **清晰**:agent 能分辨完成与未完成。模糊边界("达成了理解")导致**过早完成**:步骤尚未结束就转向下一步;
- **要求度**:逐条核对"每个修改过的 model 都已对账"比"列出变更清单"要求更高。要求度驱动**腿功**(legwork,潜藏在措辞里的挖掘,不写成独立步骤),它同样约束平铺参考:"每条规则都已应用"与"每步都做完"是同一类约束。

最强的判据既可核对又穷尽。

## 领词

**领词**(leading word)是模型已经认识的短词,例如"红绿""接缝"。正文和 description 里用同一个词,agent 更容易把触发与执行关联起来。优先使用已有的词;自造词需要正文先定义。正文里重复这个词,不重复它的定义。反面写法是用一整段解释一个概念,再在 description 里复述一遍。

**否定式**会把被禁行为带进上下文,让它更可用。因此正面表述目标行为("写一行注释"),禁令只用于无法正面表述的硬护栏,并且要同时写明正面目标。

## 修剪

- 一义一处**单一事实源**:改行为只改一处。**重复**(一义多处)付出维护与 token;
- **环境也是事实源**(`package.json` 的 scripts、配置文件、目录结构、`--help` 输出):复述环境的文档是**缓存**,只在查询昂贵时值得。但是缓存的内容限于 agent 自己查不到的:没写下来的约定、选择背后的原因、配置不说的坑;一次文件一次命令能查到的留给环境,那里不会过期;
- 每行检查**相关性**:它是否仍与文档职责相关。**沉积**(sediment)是失败形态:加是安全的、删是危险的,陈旧行不断堆积;因此逐行删除过时行;
- 逐句删除 **no-op**:模型默认就会照做的指令,说了等于没说。判据是"它改变默认行为吗?",这是模型相对的,不是读者相对的;两人有分歧时,演练一次文档而不是辩论。一句不合格,删整句而不是修剪词。领词同理:"要彻底"改变不了默认行为,换成"无情",不是换技巧。
