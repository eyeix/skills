# 深化

如何在给定依赖的前提下,安全地深化一簇浅模块。假设已掌握 [SKILL.md](SKILL.md) 的词汇:**模块**、**接口**、**接缝**、**适配器**。

## 依赖分类

评估深化候选时,先给它的依赖分类。类别决定深化后的模块如何跨接缝测试。

### 1. 进程内

纯计算、内存状态、无 I/O。总是可深化:合并模块,直接通过新接口测试。不需要适配器。

### 2. 本地可替代

有本地测试替身的依赖(PGLite 之于 Postgres、内存文件系统)。替身存在即可深化。深化后的模块在测试套件里带着替身跑,接缝是内部的;模块外部接口上不开端口。

### 3. 远程但自有(端口与适配器)

跨网络边界、但属于你自己的服务(微服务、内部 API)。在接缝上定义**端口**(接口)。深模块持有逻辑;传输作为**适配器**注入。测试用内存适配器,生产用 HTTP/gRPC/队列适配器。

推荐话术:*"在接缝上定义端口,生产实现 HTTP 适配器、测试实现内存适配器,让逻辑住在一个深模块里,尽管它跨网络部署。"*

### 4. 真外部(mock)

不受你控制的第三方服务(Stripe、Twilio 等)。深化后的模块把外部依赖作为注入的端口;测试提供 mock 适配器。

## 接缝纪律

- **一个适配器 = 假想接缝,两个适配器 = 真接缝。**没有至少两个适配器的理由(通常是生产 + 测试),不引入端口。单适配器的接缝只是间接层;
- **内部接缝 vs 外部接缝。**深模块可以有内部接缝(实现私有,自己的测试用)和接口处的外部接缝。不因为测试用了内部接缝,就把它从接口暴露出去。

## 测试策略:替换,不叠加

- 浅模块上的旧单元测试,在深化模块的接口上有了测试后就是废物;删掉;
- 在深化模块的接口上写新测试。**接口就是测试面**;
- 测试断言穿过接口的可观察结果,不断言内部状态;
- 测试应能在内部重构中存活,因为它们描述行为,不描述实现。实现一变测试就得变,说明它测过了接口以内。
